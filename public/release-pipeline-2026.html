Engineering Process · 2026 Action Plan · v4

From manual handoffs to AI-augmented release flow.

A prioritized backlog. Two tracks — engineering builds and operates; leadership owns policy and customer comms. Four phases. Each phase pays for the next.
v4 · May 2026

Problem & Target

Today

2–4 major releases per year. 5–6 weeks from cut to all customer prods. Every step from merge to prod is human-assembled. No automated regression gate. Release notes drafted after the cut. Customer impact discovered post-deploy.

Target

Continuous, feature-based delivery. Days from "Done" to live. Agents draft the manifest, notes, breaking-change diffs, and per-customer comms. Humans approve. CI gates block bad releases. Per-customer impact predicted before cut.

Phase Flow

Phase 01
Foundation
Release Engineer Agent orchestrates the pipeline. Manifest, Jira linkage, testing agents, AI release notes & comms drafts, three-tier release model, Comm SLA.
Phase 02
Intelligence
Schema-diff & breaking-change agent, customer impact + UAT scripts, deprecation runway, per-customer impact reports.
Phase 03
Automation
CI gates, deployment orchestration, observability as a release gate.
Phase 04
Closed Loop
Post-deploy correlation, rollback recommendation, deprecation auto-cleanup.

Two Tracks

ENG · Engineering Track

Build and operate the agents, data plumbing, test infrastructure, and gates. Human-in-the-loop on agent outputs that govern code, tests, and release correctness.

LEAD · Leadership Track

Set policy, own customer-bound communication, govern the program, and measure outcomes. Human-in-the-loop on agent outputs that go to customers.

Initiative Backlog

Items grouped by phase. Each phase builds on the previous — but engineering and leadership work in parallel within a phase. Priority is independent of phase: a "Critical" item in Phase 2 still ships before any "Medium" item in Phase 1.

E-00 Eng Release Engineer Agent (orchestrator) The conductor of the end-to-end pipeline. Listens to system events — MR merge, branch cut, CI green, RC sign-off, deploy complete, alert fired — and triggers the right downstream agent at the right step. Routes escalations to humans at the right gates. Maintains a single source of truth for where every release stands. Every other agent in this plan plugs into its event bus and reports state back. Outcomes by Phase

Phase 01

Single source of truth + customers feel it. Release Engineer Agent coordinates the pipeline. Notes auto-drafted in <1h. Per-customer comms drafted from the impact map. Three-tier model and Comm SLA stop the per-cycle re-debate.

Phase 02

Customer-specific intelligence. Breaking changes flagged before the cut. Per-customer impact reports replace generic blasts. UAT scripts travel with every implementation.

Phase 03

Gates do the gating. CI Green is mandatory. Deployment cadence is automated. Observability alerts before customers do.

Phase 04

Closed loop. Post-deploy issues correlate to MRs. Rollback gets evidence. Deprecation cleanup runs on rails.

Guiding Principles

Non-negotiables
  • The agent replaces data gathering, not human judgment.
  • Every customer-bound output has a leadership approval gate.
  • Every code-bound output has an engineering review.
  • Phases are sequential at the macro level; in-phase work runs in parallel.
  • Priority is independent of phase — Critical items in Phase 2 ship before Medium items in Phase 1.
  • We don't gate any phase on perfection of the previous.
