Support Process · 2026 Action Plan · v1

From manual triage to AI-augmented support flow.

Every customer ticket lives in a per-client Jira project. Agents groom, triage, and route inside Jira — three support levels, every customer-bound comment approved until trust is earned, every feature signal lands on the product ideas board.
v1 · May 2026

Problem & Target

Today

Tickets arrive incomplete; humans chase customers for repro details. Triage is tribal — whoever picks up the ticket decides where it goes. L1 questions (config, how-to) eat engineering time. Customers wait in silence while a ticket sits. Feature requests get lost in comment threads. The same issue surfaces three times before anyone notices the pattern.

Target

Tickets are acknowledged in seconds and groomed within minutes. A triage agent classifies every ticket into L1 / L2 / L3 / Feature. L1 answers are drafted from product docs and past tickets; L2 prepares devs with code locations and repro; L3 humans code on agent-prepped tickets. Feature requests auto-create a vx ticket on the ideas board. The customer hears something at every step.

Three Levels + Feature Path

Level 01
Agent-led answer

Config change, platform how-to, known issue. Agent drafts, CIE approves in V1; agent auto-posts above confidence threshold in Phase 04. Grounded in KB + resolved tickets.

Level 02
Agent-guided dev

Deeper issue; likely needs code. Agent guides a viax developer with suspected code locations, repro, and similar past fixes — or flags the issue as architectural and escalates.

Level 03
Human code change

Architectural or non-trivial. Human dev makes the change on an agent-prepped ticket (repro, code map, customer impact already attached). Agents draft code suggestions later, once trust is earned.

Feature
vx ticket to Product

Not a bug — a feature ask. Agent creates a vx ticket on the product ideas board with original context, customer, and signal weight. Product prioritizes on cadence.

Phase Flow

Phase 01
Foundation
Support Coordinator orchestrates the pipeline. Grooming, auto-ack, PII scrubbing live. Three-level model, comm SLA, approval policy.
Phase 02
Triage & Resolution
Triage agent classifies. KB/RAG feeds L1 answers. Sentiment + VIP flags. Status updates while customers wait. vx tickets reach Product.
Phase 03
Diagnostic Depth
L2 dev guidance. KB capture from every resolution. Hotspot detection. Post-resolution QA + CSAT. Eval harness keeps agents honest.
Phase 04
Autonomy
L1 auto-posts above confidence threshold. Agent-assisted L3 code suggestions. Regression tests captured from resolved bugs.

Two Tracks

ENG · Engineering Track

Build and operate the agents, KB ingestion, Jira integration, eval harness, observability. Human-in-the-loop on every code-bound output — L2 guidance, L3 code suggestions, dev-facing recommendations all reviewed by a viax engineer.

LEAD · Support & Product Leadership

Own customer-bound communication, support policy, escalation playbook, CSAT, and vx prioritization. Human-in-the-loop on every customer-bound Jira comment until confidence threshold and evals warrant unattended auto-post.

Initiative Backlog

Items grouped by phase. Each phase builds on the previous — but engineering and leadership work in parallel within a phase. Priority is independent of phase: a "Critical" item in Phase 2 still ships before any "Medium" item in Phase 1.

Phase 01 — Foundation Orchestrator, intake hygiene, policy. The floor everything else builds on. Eng × Lead in parallel
S-00 Eng Support Coordinator Agent (orchestrator) The conductor of the end-to-end support pipeline. Listens to per-client Jira events — ticket created, comment added, status change, transition — and triggers the right downstream agent at the right step. Maintains a single state machine per ticket. Routes escalations to humans at the right gates. Every other agent in this plan plugs into its event bus and reports state back through Jira. Critical —
S-01 Eng Ticket Grooming agent Checks every new ticket against a required-fields schema (steps to repro, expected vs. actual, environment, build version, customer impact). If anything is missing, comments on the Jira ticket asking the customer for it — in plain language, with a checklist. Re-checks after each customer reply until the ticket is groom-complete. Critical S-00
S-02 Eng Auto-acknowledgment agent First Jira comment posts within seconds of ticket creation: confirms receipt, sets expectation by severity (per SLA matrix), and tells the customer what happens next. Sets the tone — no ticket sits silent. Critical S-00L-02

L-01 Lead Three-level support model (L1/L2/L3/Feature) Formalized: each level's scope, who owns each level, what gets escalated and when, what the customer is told at each step. Feature path includes vx ticket creation criteria. Documented in Confluence. Critical —
L-02 Lead Customer comms SLA matrix First-response, status-update cadence, and resolution target by severity (P0 / P1 / P2 / P3) and customer tier (VIP / strategic / standard). Channel = Jira comment. Confluence as system of record. Critical —

Outcomes by Phase

Phase 01

No ticket sits silent. Auto-ack in seconds. Grooming agent collects missing info without a human in the loop. PII scrubbed at the gate. Three-level model + comm SLA + approval policy end the per-ticket re-debate.

Phase 02

Triage stops being tribal. Every groom-complete ticket gets classified, severity-tagged, and routed. L1 answers drafted from KB. Customers hear updates while they wait. Feature requests reach Product as vx tickets.

Phase 03

Devs go from cold to coding in minutes. L2 diagnostic agent surfaces likely cause + code locations. Hotspot signal reaches Eng + Product early. KB grows on its own with every resolution.

Phase 04

Autonomy earned, not assumed. L1 agent auto-posts above the confidence threshold. L3 code suggestions land in MR drafts for human review. Bugs become regression tests in the release pipeline.

Guiding Principles

Non-negotiables
  • Agents replace data gathering, not human judgment.
  • Every customer-bound Jira comment is CIE-approved until evals + threshold warrant auto-post.
  • Every code-bound output has engineering review — L2 guidance, L3 suggestions, all of it.
  • Customers are told when an agent is responding — bot signature, no impersonation.
  • Trust is earned per agent, measured by evals, granted by L-09 criteria.
  • PII is scrubbed at the gate before any LLM call. No exceptions.
  • Phases are sequential at the macro level; in-phase work runs in parallel.
  • Priority is independent of phase — Critical in Phase 2 ships before Medium in Phase 1.
